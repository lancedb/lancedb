A [Secret](/governance/secrets) is a named credential that Functions bind by
reference. These statements store, rotate, list, describe and drop Secrets.

A Secret is addressed like a table: `[db.][namespace.]name`. An unqualified
name uses the session's database and namespace. A nested namespace is one
backtick-quoted name with `$` between its components, and `public` is the
database's root namespace. A Secret name may contain letters, digits, `_`, `.`
and `-`, so quote one that contains `.` or `-`:

```sql
api_key
platform.`openai-prod`
analytics.`ml$vision`.`openai-prod`
```

`CREATE`, `ALTER` and `DROP` return one row of `operation`, `name` and
`status`. Without `IF [NOT] EXISTS`, a taken name (for `CREATE`) or a missing
Secret (for `ALTER` and `DROP`) is an error rather than a status.

## CREATE SECRET {#create}

```sql
CREATE SECRET platform.`openai-prod` WITH (value = 'sk-...')
CREATE SECRET IF NOT EXISTS api_key WITH (value = $$sk-...$$)
```

Stores a new Secret. The value may be single-quoted or dollar-quoted. Requires
`CREATE SECRET` on the namespace; the caller becomes the Secret's owner.

The status is `created`, or `already_exists` with `IF NOT EXISTS`. It never
overwrites an existing Secret; use `ALTER SECRET`.

## ALTER SECRET {#alter}

```sql
ALTER SECRET platform.`openai-prod` SET WITH (value = 'sk-...')
ALTER SECRET IF EXISTS api_key SET WITH (value = $$sk-...$$)
```

Replaces the Secret's value. Every Function bound to it gets the latest value in
the next work it starts, including in jobs already running, without a new
Function version. Requires `UPDATE` on the Secret.

The status is `altered`, or `not_found` with `IF EXISTS`.

## DROP SECRET {#drop}

```sql
DROP SECRET platform.`openai-prod`
DROP SECRET IF EXISTS api_key
```

Deletes the Secret and every grant on it. Functions bound to it fail at their
next job, naming the Secret. Requires `OWNERSHIP` on the Secret.

The status is `dropped`, or `not_found` with `IF EXISTS`.

<Warning>
`DROP SECRET` cannot be undone. A new Secret created under the same name is
picked up by every Function still bound to that name.
</Warning>

## SHOW SECRETS {#show}

```sql
SHOW SECRETS
SHOW SECRETS IN platform
SHOW SECRETS IN analytics.`ml$vision`
SHOW SECRETS IN public
```

Lists the Secret names in one namespace as a sorted `name` column. Without
`IN`, it lists the session's namespace; `IN public` lists the root. Requires
`USAGE` on the database and the namespace.

## DESCRIBE SECRET {#describe}

```sql
DESCRIBE SECRET platform.`openai-prod`
DESC SECRET api_key
```

Returns one row:

| Column | Type | Meaning |
| --- | --- | --- |
| `name` | string | The Secret's name |
| `created_at_millis` | int64 | When it was created, in milliseconds since the Unix epoch |
| `updated_at_millis` | int64 | When its value was last set. Watch this change to confirm a rotation landed. |
| `history` | list of struct `{generation: uint64, at_millis: int64}` | Creation and each rotation since, oldest first, up to the most recent 100 |

A missing Secret is an error. Requires `USAGE` on the Secret.

## GRANT and REVOKE {#grant}

```sql
GRANT CREATE SECRET ON SCHEMA platform TO ROLE platform_admins
GRANT USAGE ON SECRET platform.`openai-prod` TO ROLE research
GRANT USAGE, UPDATE ON SECRET platform.`openai-prod` TO ROLE etl, rotation_service
GRANT OWNERSHIP ON SECRET platform.`openai-prod` TO ROLE platform_admins
REVOKE UPDATE ON SECRET platform.`openai-prod` FROM ROLE etl
```

| Object | Privileges |
| --- | --- |
| `SECRET` | `OWNERSHIP`, `USAGE` (bind it to a Function), `UPDATE` (rotate it) |
| `SCHEMA` (a namespace) | `CREATE SECRET` |

The caller must own the object. Grantees are roles only. Returns one row per
privilege and role, with status `granted`, `already_granted`, `revoked` or
`not_granted`.

- A statement applies all of its changes or none of them.
- Granting a privilege a role already holds, or revoking one it does not hold,
  is a no-op.
- `OWNERSHIP` cannot be revoked. Granting it transfers it, to one role only.
- Neither the Secret nor the role has to exist, so a misspelled name still
  reports `granted`.
- An unquoted role name is lowercased. Quote a role whose name has capitals:
  `TO ROLE "DataEng"`.

## The value stays out of output {#redaction}

A Secret's value never appears in a statement's result, an error message,
`EXPLAIN` output, or the query log. The query log masks everything from `WITH`
onward in a Secret statement.

<Note>
SQL has no syntax for binding a Secret to a Function. Register Functions that
bind Secrets through the Python SDK or REST; see
[Secrets](/governance/secrets#quickstart).
</Note>
