<Badge color="red">Enterprise</Badge> [SQL runs in LanceDB Enterprise.](/sql)

There is no SQL type layer over Lance storage. The table provider hands
DataFusion the dataset's Arrow schema directly, so a column is the same object
to the query engine as it is to the format.

The consequence is that SQL type names here are **spellings of Arrow types**,
not a system that maps onto them. [Data types](/sql/data-types) documents the
storage side; this page covers what changes when you reach a column from SQL.

## The Arrow types a column can be {#supported}

| Category | Types |
| --- | --- |
| Null | `null` |
| Boolean | `bool` |
| Integer | `int8`, `int16`, `int32`, `int64` and their `uint` counterparts |
| Floating point | `float16`, `float32`, `float64` |
| String | `utf8`, `large_utf8` |
| Binary | `binary`, `large_binary`, `fixed_size_binary(n)` |
| Date and time | `date32`, `date64`, `time32`, `time64`, `timestamp` (with or without timezone), `duration` |
| Nested | `struct`, `list`, `large_list`, `fixed_size_list`, `map` |
| Dictionary | `dictionary(key, value)` |

Two limits are worth stating because they surface as schema errors rather than
as documentation:

- A `map` with `keys_sorted = true` is rejected. Sorted-key maps do not survive
  the round trip through the Python bindings, so they are refused rather than
  silently unsorted.
- Not every type is legal as a `fixed_size_list` child. The vector case is,
  which is what matters in practice.

## SQL names for Arrow types {#names}

| SQL | Arrow |
| --- | --- |
| `BOOLEAN` | `Boolean` |
| `TINYINT` `SMALLINT` `INT` `BIGINT` | `Int8` `Int16` `Int32` `Int64` |
| `UTINYINT` … `UBIGINT` | the unsigned counterparts |
| `REAL` / `FLOAT` | `Float32` |
| `DOUBLE` | `Float64` |
| `VARCHAR` / `TEXT` / `STRING` | `Utf8` |
| `BYTEA` / `BINARY` | `Binary` |
| `DATE` | `Date32` |
| `TIME` | `Time64` |
| `TIMESTAMP` | `Timestamp`, with or without a timezone |
| `INTERVAL` | `Interval` |
| `STRUCT` / `LIST` / `MAP` | the nested equivalents |

DataFusion's [type reference](https://datafusion.apache.org/user-guide/sql/data_types.html)
describes the full mapping.

## Types SQL has no name for {#no-name}

Three column kinds you will meet that no SQL type name covers.

### Vectors {#vectors}

A dense vector column has a fixed dimension, commonly represented as
`FixedSizeList<Float32, dim>`. Other supported vector element types are
possible; inspect the column with [`arrow_typeof`](/sql/scalar-functions#type) rather than assuming Float32.
It is selectable and testable for nullness:

```sql
SELECT id FROM documents WHERE vector IS NOT NULL
```

<Warning>
A list representation does not imply that ordinary arithmetic operators
perform vector arithmetic. Use supported distance functions for similarity
calculations. SQL vector search depends on the Enterprise server version and query
plan; see [SQL](/basics/sql#no-vector-sql).
</Warning>

### JSON {#json}

Stored as JSONB in `large_binary` with the `lance.json` extension name. It reads
through accessor functions rather than a `->` operator:

```sql
SELECT json_get_string(data, 'name') FROM events
WHERE json_get_int(data, 'status') = 200
```

`json_get`, its typed variants, and `json_extract` are **index-accelerated** by a
JSON scalar index. See [Functions](/sql/scalar-functions#json).

### Blobs {#blobs}

A blob column with the `lance.blob.v2` extension stores binary payloads.
SQL queries return a blob column as a descriptor struct
rather than raw bytes, so scanning or filtering a table doesn't open the
underlying blob files.

#### Descriptor fields {#blob-descriptor-fields}

| Field | SQL type | Arrow type | Description |
| --- | --- | --- | --- |
| `kind` | `UTINYINT` | `UInt8` | `0` inline, `1` packed sidecar, `2` dedicated sidecar, `3` an external object referenced by URI. |
| `position` | `UBIGINT` | `UInt64` | Byte offset of the payload. For blobs stored in the table, the offset can change across flush or compaction. For an external object, this is the start of the referenced range, or `0` when the range starts at the beginning of the object. |
| `size` | `UBIGINT` | `UInt64` | Payload length in bytes. For inline, packed, and dedicated blobs, `0` is an empty payload. For an external object with no byte range, `0` means the length is resolved when the object is read. |
| `blob_id` | `UINT` | `UInt32` | Sidecar file identifier for packed and dedicated blobs. For an external blob, `0` means `blob_uri` is an absolute URI. A non-zero value selects a registered base path. |
| `blob_uri` | `VARCHAR` | `Utf8` | Empty for blobs stored in the table. For an external blob, the object URI, or a path relative to the base selected by `blob_id`. |

Select the whole column to read its descriptor:

```sql
SELECT id, payload
FROM documents
WHERE payload IS NOT NULL
```

For example, a 2 MiB video stored in a packed sidecar returns:

```text
{
  kind:     1,
  position: 4194304,
  size:     2097152,
  blob_id:  3,
  blob_uri: ""
}
```

#### Notes and limits {#blob-sql-limits}

- SQL doesn't return blob bytes. Read bytes through the SDKs with
  `fetch_blobs`, `fetch_blob_files`, or `fetch_blob_ranges`.
- Referencing a single descriptor field, such as `payload.size` or
  `payload.kind`, isn't supported. Depending on how the table was created,
  it fails during planning or reads the wrong value. Select the whole
  `payload` column instead.
- Use `payload IS NULL` or `payload IS NOT NULL` to find NULL blobs.
- `data` is a write input, not a descriptor field, and can't be queried.

See [Multimodal data](/management/table#multimodal-blob-v2) for
defining blob columns and fetching byte ranges through the SDKs.

### bfloat16 {#bfloat16}

Sixteen-bit floats in the bfloat16 layout, stored as `fixed_size_binary(2)`.
Useful as a vector element type when halving the memory matters more than the
precision does.

## Geospatial {#geospatial}

<Warning>
Lance defines geospatial types and `st_*` functions on
[GeoArrow](https://geoarrow.org), but they sit behind an optional build feature
that **LanceDB does not ship**. Calling `st_intersects` and friends returns an
error naming the missing feature rather than an unknown-function error, and the
spatial index is gated the same way.
</Warning>

Geometry can still be stored (it is binary, and binary columns work), but
nothing interprets it. Filter on a bounding box held in ordinary numeric
columns if you need spatial predicates today.

## Pseudo-columns {#pseudo-columns}

Availability depends on the SQL table provider. The ordinary table provider
exposes the stored dataset schema; naming a Lance scan metadata field does
not make it available as a SQL column. The `fts()` provider adds `_score` to
its schema, so `_score` is included in `SELECT * FROM fts(...)`.

| Column | Type | |
| --- | --- | --- |
| `_rowid` | `UInt64` | Lance scan row identifier; stability requires stable row ids |
| `_rowaddr` | `UInt64` | physical row address |
| `_rowoffset` | `UInt64` | offset within the fragment |
| `_score` | `Float32` | relevance, from [`fts()`](/sql/functions#fts) |

`_rowid`, `_rowaddr`, and `_rowoffset` describe Lance scan metadata, not
columns automatically registered on an ordinary SQL table. Select `_score`
from an `fts()` relation explicitly when you want a projection containing it.

## Casting {#casting}

```sql
SELECT CAST(identifier AS VARCHAR) FROM documents
SELECT TRY_CAST(maybe_number AS BIGINT) FROM raw
```

`TRY_CAST` yields null rather than failing the query on a value that will not
convert. See [Operators](/sql/operators#casting).
