```text
cosine_distance  distance  exact_distance  inner_product
```

<Warning>
Distance functions can evaluate arrays per row. Some deployment versions also
recognize `ORDER BY distance(vector, query_vector) LIMIT k` over a table scan
and plan it as vector search, with indexed or flat search as appropriate.
Where available, `exact_distance` evaluates distance without that rewrite.
Confirm the functions supported by your deployment and inspect SQL
[`EXPLAIN`](/sql/dql/explain); the function name alone does not guarantee an
index-backed plan. See [SQL vector search](/basics/sql#no-vector-sql).
</Warning>

A third, optional argument is a comma-separated options string. `metric`
selects `l2` (default, alias `euclidean`), `cosine`, or `dot`; the
index-search rewrite also reads `nprobes` and `use_index`:

<CodeGroup>
```sql SQL icon="database"
SELECT id FROM documents
ORDER BY distance(embedding, ARRAY[0.1, 0.2, 0.3], 'metric=cosine,nprobes=20')
LIMIT 10

-- Force a flat scan, bypassing the index:
SELECT id FROM documents
ORDER BY exact_distance(embedding, ARRAY[0.1, 0.2, 0.3], 'use_index=false')
LIMIT 10
```
</CodeGroup>
