```sql SQL icon="database"
[WITH cte AS (...)]
SELECT [ALL | DISTINCT] select_expr [, ...]
FROM from_item [[JOIN ...] ON ...]
[WHERE predicate]
[GROUP BY expr [, ...]] [HAVING predicate]
[WINDOW name AS (...)]
[ORDER BY expr [ASC | DESC] [NULLS FIRST | LAST] [, ...]]
[LIMIT n] [OFFSET n]
```
</CodeGroup>

## Projection {#projection}

<CodeGroup>
```sql SQL icon="database"
SELECT id, title, identifier FROM documents
```

```python Python icon="python"
tbl.search().select(["id", "title", "identifier"]).to_arrow()
```

```typescript TypeScript icon="square-js"
await tbl.query().select(["id", "title", "identifier"]).toArrow();
```
</CodeGroup>

Name the columns you need instead of using `SELECT *`, particularly for
tables containing images, video or large vectors. Projection lets the engine
avoid loading unnecessary columns, although columns used by filters, joins or
other expressions may still need to be read.

Row metadata is available as [pseudo-columns](/sql/data-types#pseudo-columns)
(`_rowid`, `_rowaddr`, `_rowoffset`) but only when named, so they stay out of
`SELECT *`.

`DISTINCT` deduplicates the projected rows.

## Filtering {#filtering}

<CodeGroup>
```sql SQL icon="database"
SELECT * FROM documents
WHERE identifier > 0 AND identifier < 1000000
```

```python Python icon="python"
tbl.search().where("identifier > 0 AND identifier < 1000000").to_arrow()
```

```typescript TypeScript icon="square-js"
await tbl.query().where("identifier > 0 AND identifier < 1000000").toArrow();
```
</CodeGroup>

The SDK `where` takes the same expression language, so a predicate moves between
them unchanged. A supported predicate can use a scalar index; confirm the chosen plan with
[`explain_plan`](/search/explain). See
[Filtering](/search/filtering) for the operators and their pushdown behaviour.

## Ordering and limiting {#order-limit}

<CodeGroup>
```sql SQL icon="database"
SELECT id, title FROM documents
ORDER BY created_at DESC NULLS LAST
LIMIT 100 OFFSET 200
```
</CodeGroup>

`ORDER BY` on a large table is a sort over the whole result, so pair it with a
`LIMIT` unless you genuinely need every row ordered.

## Set operations {#set-operations}

`UNION`, `UNION ALL`, `INTERSECT` and `EXCEPT` combine whole queries:

<CodeGroup>
```sql SQL icon="database"
SELECT id FROM documents WHERE category = 'film'
UNION ALL
SELECT id FROM archived_documents WHERE category = 'film'
```
</CodeGroup>

`UNION` deduplicates and `UNION ALL` does not, which makes `UNION ALL` the
cheaper one when you already know the inputs are disjoint.

## Common table expressions {#ctes}

<CodeGroup>
```sql SQL icon="database"
WITH recent AS (
    SELECT * FROM documents WHERE created_at > now() - INTERVAL '7 days'
)
SELECT category, count(*) FROM recent GROUP BY category
```
</CodeGroup>

A CTE is scoped to the statement. One you want to keep is a
[view](/management/view); one whose rows you want stored is a
[materialized view](/management/materialized-view).

## Subqueries {#subqueries}

Subqueries are allowed anywhere an expression or a relation is (in `FROM`, in
`WHERE` with `IN` or `EXISTS`, and as a scalar in the select list):

<CodeGroup>
```sql SQL icon="database"
SELECT title
FROM documents
WHERE category_id IN (SELECT id FROM categories WHERE active)
```
</CodeGroup>

## Namespaced tables {#namespaces}

A table inside a [namespace](/management/namespace) is written as a dotted path:

<CodeGroup>
```sql SQL icon="database"
SELECT * FROM prod.events.clicks
```
</CodeGroup>

## Reading the plan {#plans}

`EXPLAIN` and `EXPLAIN ANALYZE` work as DataFusion defines them, and produce the
same operators the SDK methods do:

<CodeGroup>
```sql SQL icon="database"
EXPLAIN ANALYZE SELECT * FROM documents WHERE identifier < 1000
```
</CodeGroup>

See [Explain](/search/explain) and [Explain Analyze](/search/explain).
