<CodeGroup>
```sql SQL icon="database"
SELECT id, blob_descriptor(video) AS descriptor FROM videos
```
</CodeGroup>

A [BlobV2](/management/table#managed-blobs) column's bytes are not fetched by
a plain `SELECT`: that already returns `large_binary`, the same as any other
binary column. `blob_descriptor` instead returns a small struct describing
where the payload lives, without reading it. Pass one row's descriptor to
the SDK's blob file reader to open that payload directly:

<CodeGroup>
```python Python icon="python"
rows = db.execute_query("SELECT id, blob_descriptor(video) AS descriptor FROM videos").read_all().to_pylist()
with table.open_blob_file(rows[0]["descriptor"]) as reader:
    payload = reader.read()
```
</CodeGroup>

A descriptor is pinned to the table version it was read at: it keeps
resolving correctly even after the table is appended to and checked out to a
newer version.
