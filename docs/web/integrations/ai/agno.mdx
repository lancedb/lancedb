[Agno](https://docs.agno.com/introduction) builds agents that can search an external knowledge base before they answer.
Its `LanceDb` adapter writes chunk embeddings, text, and metadata into one LanceDB table.
Pass that adapter to a `Knowledge` object, then pass the object to an `Agent`.

With `search_knowledge=True`, the model receives a `search_knowledge_base` tool.
Agno runs the tool against LanceDB and feeds the returned chunks back into the answer.
That is the retrieval memory for documents you have ingested.
Conversational user memories created with `enable_agentic_memory` stay in Agno's session database.

## Install Agno and LanceDB {#install-agno-and-lancedb}

<CodeGroup>
```bash pip icon="terminal"
pip install -U agno lancedb openai
```

```bash uv icon="terminal"
uv add agno lancedb openai
```
</CodeGroup>

Export an OpenAI key before you embed or ask a question:

```bash
export OPENAI_API_KEY=sk-...
```

Install `pypdf` when you insert PDF files or PDF URLs. The text notes below do not need it.

## Store notes and ask an agent {#store-notes-and-ask-an-agent}

A directory URI opens a LanceDB Embedded database on disk.
`SearchType.hybrid` runs vector search and LanceDB full-text search on the same query.
`OpenAIEmbedder` is the default embedder. Set `id` when you want a specific model.
`text-embedding-3-small` uses 1536 dimensions.

<CodeBlock filename="Python" language="Python" icon="python">
  {PyFrameworksAgnoQuickstart}
</CodeBlock>

`knowledge.insert()` chunks the text, embeds each chunk, and adds the rows to the LanceDB table.
Pass `name` so you can delete that document later.

Attach the same `Knowledge` object to an agent.
`search_knowledge` defaults to `True`. The example sets it explicitly.

<CodeBlock filename="Python" language="Python" icon="python">
  {PyFrameworksAgnoAsk}
</CodeBlock>

The agent calls LanceDB, then answers from the retrieved notes.
A local table lives in the directory you passed as `uri`.

## Read the retrieved chunks {#read-the-retrieved-chunks}

`knowledge.search()` returns the same chunks the agent would see, without calling the chat model.
The query is still embedded.

  {PyFrameworksAgnoSearch}
</CodeBlock>

Each result is a document with `name`, `content`, and `meta_data`.

## Choose vector, keyword, or hybrid search {#choose-vector-keyword-or-hybrid-search}

Set `search_type` on the `LanceDb` instance. You can change it later on the same object.

| `search_type` | What LanceDB runs |
|:---|:---|
| `SearchType.vector` | Nearest vectors for the embedded query. This is the default. |
| `SearchType.keyword` | Full-text search over the stored payload. Agno creates the FTS index on first use. |
| `SearchType.hybrid` | Vector search and full-text search together. Agno drops duplicate chunks. |

<CodeBlock filename="Python" language="Python" icon="python">
  {PyFrameworksAgnoSearchMode}
</CodeBlock>

Keyword search is the right mode when the question contains a name, an id, or another exact string.
Vector search matches paraphrases. Hybrid search keeps both signals.

Dictionary `filters` are applied in Agno after LanceDB returns candidates, so a filtered call can return fewer rows than `max_results`.
Filter-expression lists are ignored by this adapter.
Prefer `user_id` when you need the filter to run inside LanceDB.

## LanceDb parameters {#lancedb-parameters}

| Name | Type | Purpose | Default |
|:---|:---|:---|:---|
| `uri` | `str` | Directory for LanceDB Embedded, or a `db://` URI for LanceDB Enterprise. | `/tmp/lancedb` |
| `table_name` | `str` | Table that stores chunks. Required when `table` is omitted. | none |
| `table` | `LanceTable` | Existing table to reuse. | none |
| `connection` | `DBConnection` | Existing LanceDB connection. Otherwise Agno calls `lancedb.connect`. | none |
| `api_key` | `str` | API key for a `db://` URI. Falls back to `LANCEDB_API_KEY`. | none |
| `embedder` | `Embedder` | Embeds chunks and queries. `dimensions` must be set. | `OpenAIEmbedder()` |
| `search_type` | `SearchType` | `vector`, `keyword`, or `hybrid`. | `SearchType.vector` |
| `distance` | `Distance` | `cosine`, `l2`, or `max_inner_product`. Import it from `agno.vectordb.distance`. | `Distance.cosine` |
| `nprobes` | `int` | IVF probes for vector search. | none |
| `on_bad_vectors` | `str` | `error`, `drop`, `fill`, or `null`. | none |
| `fill_value` | `float` | Fill value when `on_bad_vectors` is `fill`. | none |
| `reranker` | `Reranker` | Deprecated on `LanceDb`. Pass the reranker to `Knowledge` instead. | none |

`knowledge.ainsert()` and `knowledge.asearch()` are the async entry points.
The LanceDB adapter embeds asynchronously, then writes and searches through the synchronous table.

## Scope notes to one user {#scope-notes-to-one-user}

Pass `user_id` to store chunks for one user.
A search with that `user_id` returns the user's rows plus shared rows.
Shared rows are inserts that omit `user_id`.
A search that omits `user_id` reads every row.

<CodeBlock filename="Python" language="Python" icon="python">
  {PyFrameworksAgnoUserScope}
</CodeBlock>

LanceDB stores `user_id` as its own column and applies it with a prefilter, so the owner check happens before the top-k cutoff.

## Delete notes {#delete-notes}

`delete_by_name()` removes every chunk inserted under that name.
`delete_by_metadata()` matches the dictionary you stored on `metadata`.

<CodeBlock filename="Python" language="Python" icon="python">
  {PyFrameworksAgnoDelete}
</CodeBlock>

`vector_db.drop()` drops the whole LanceDB table.

## Connect to LanceDB Enterprise {#connect-to-lancedb-enterprise}

A `db://` URI stores the same knowledge table in LanceDB Enterprise.
Set `LANCEDB_URI` to that URI and `LANCEDB_API_KEY` to the database API key.
A `db://` URI without an API key raises `ValueError`.

<CodeBlock filename="Python" language="Python" icon="python">
  {PyFrameworksAgnoEnterprise}
</CodeBlock>

Pass `enterprise_db` to `Knowledge` the same way as the local `vector_db`.

## Use a local Ollama embedder {#use-a-local-ollama-embedder}

Install Ollama, pull an embedding model, and install the Python client with `pip install ollama`.
Set `dimensions` to the size of that model. `nomic-embed-text` uses 768.
Store those vectors in `agent_notes_ollama`.
The OpenAI quickstart writes 1536-dimensional vectors to `agent_notes` in the same directory, and a later search fails when the query width does not match that column.
Insert the notes with the Ollama embedder, then search `agent_notes_ollama`.

<CodeBlock filename="Python" language="Python" icon="python">
  {PyFrameworksAgnoOllama}
</CodeBlock>

The embedder calls your local Ollama server. The `Ollama` chat model does too, when you use it for the answer.
See Agno's embedder guide: [Ollama embedder](https://docs.agno.com/knowledge/concepts/embedder/ollama/ollama-embedder).

## Ask questions about a YouTube transcript {#ask-questions-about-a-youtube-transcript}

The same `Knowledge` object can index a transcript instead of short notes.
This walkthrough builds a CLI assistant that:

- Fetches a transcript with the YouTube API
- Stores embeddings and metadata in LanceDB
- Retrieves context with hybrid search
- Answers follow-up questions in a loop

Install the extra packages for this walkthrough:

## Why this works well {#why-this-works-well}

LanceDB Embedded reads and writes a local directory, so the knowledge table can stay on your machine.

- One `Knowledge` object, backed by LanceDB, defines both ingestion and search.
- Vector search, full-text search, and hybrid search are a `search_type` change on that same table.
- `user_id` keeps one user's notes in the table without a second database.
- The same `uri` and `table_name` open the table again the next time the agent starts.

As the table grows, move the `uri` to LanceDB [Enterprise](/index#architecture) for automatic compaction, reindexing, and larger datasets.
