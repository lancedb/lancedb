## Which limits apply? {#scope}

Some limits come from an API or data type; others come from Enterprise
configuration. Use the scope and linked reference below to identify which
applies to your operation. SQL and server job limits apply to Enterprise.

<span id="names" />

[Naming Rules](/basics/naming) is the reference for name lengths, characters and
namespace depth. Client and server versions can differ in which rules they
enforce.

## What are the fixed limits? {#fixed-limits}

| Operation | Scope | Limit and behavior |
| --- | --- | --- |
| Job event retrieval | Enterprise | At most 10,000 rows per response. Results can be truncated without a truncation indicator. |
| `SHOW ERRORS ... LIMIT` | Enterprise SQL | Accepts 1 through 100,000. Values outside the range are rejected. |
| `SHOW ERRORS` without `FOR JOB` | Enterprise SQL | Inspects up to the 32 most recent failed jobs. Use `FOR JOB` to inspect a specific job. |
| Percentage sampling | Enterprise SQL | `TABLESAMPLE` accepts percentages from 0 through 100. Values outside the range are rejected. |
| Row-count sampling | Enterprise SQL | `TABLESAMPLE (... ROWS)` requires a whole number. |

See [SQL job commands](/sql/ddl/job#errors) and
[Sampling](/sql/dql/sampling) for syntax and restrictions on supported table types.

<span id="schema" />

Data-type and index constraints belong to the operation you choose. Check
[Data types](/sql/data-types) and [Vector indexes](/indexing/vector-index)
before choosing a schema or index. For materialized views, check
[stable row ID requirements](/feature-engineering/materialized-views#stable-row-ids)
before creating source tables.

## What can you configure? {#not-quotas}

| Setting | What it controls |
| --- | --- |
| Job event `limit` | Requests more or fewer event rows. The default is 1,000; the 10,000-row maximum still applies. |
| FTS `max_token_length` | The maximum indexed token length. The default is 40; longer tokens are excluded from the index. |
| Enterprise capacity and quotas | Storage, request rate and concurrency are governed by your deployment's resources and configuration. Confirm these with your administrator or LanceDB support. |

## What happens at a limit? {#behavior}

- **Rejected requests:** correct the input before retrying, such as a sampling
  percentage outside the accepted range.
- **Truncated responses:** do not assume that a returned event list is the full
  history. Increasing `limit` cannot exceed the maximum; use filters to narrow
  the events you inspect.
- **Excluded data:** an FTS token-length setting can affect which words are
  searchable. Choose it for your text and indexing requirements.
