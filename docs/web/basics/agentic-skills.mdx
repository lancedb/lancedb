A coding agent writing LanceDB code from memory writes whatever was in its
training data -- often an older API, sometimes one that never existed. The
LanceDB agent plugin fixes that by supplying the current reference at the point
the agent needs it.

## The plugin {#plugin}

It ships as the `lancedb` plugin in the
[lancedb-agent-plugins](https://github.com/lancedb/lancedb-agent-plugins)
repository, which doubles as a plugin marketplace. It covers the Python and
TypeScript APIs, which code is portable between a local database and a
deployment, ingestion performance, and branch operations.

<CodeGroup>
```text Claude Code
/plugin marketplace add lancedb/lancedb-agent-plugins
/plugin install lancedb@lancedb
```

```bash Codex icon="terminal"
codex plugin marketplace add lancedb/lancedb-agent-plugins
codex plugin add lancedb@lancedb
```

```bash Other agents icon="terminal"
npx plugins add lancedb/lancedb-agent-plugins
```
</CodeGroup>

The cross-tool installer detects which agent CLIs are on your `PATH` -- Cursor,
GitHub Copilot CLI, VS Code, Grok Build, Kimi Code, Claude Code, Codex -- and
installs through each one's native plugin system.

## What agents are good at here {#workflows}

Two things about LanceDB make it unusually agent-friendly, and both have a
worked tutorial.

The second is the more interesting pattern. [Branches](/tables/versioning)
give an agent somewhere to be wrong safely: it can rewrite a schema, recompute a
column, or try three embedding models without touching `main`, and you keep only
what measured better.
