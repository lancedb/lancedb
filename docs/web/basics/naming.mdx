## What can you name? {#objects}

Databases, namespaces, tables, views and branches all have names. Choose names
that describe their purpose, such as `documents`, `prod` or `training_2026`.
Consistent names make data easier to find and application code easier to read.

## What makes a valid name? {#rules}

Use these naming constraints when creating objects. Some OSS backends and older
clients accept names outside these bounds; that does not make those names
portable to Enterprise or another namespace implementation.

| Object | Characters | Length |
| --- | --- | --- |
| Table, materialized view, view | ASCII letters and digits, `-`, `_`, `.` | 1 to 128 characters |
| Namespace component | ASCII letters and digits, `-`, `_`, `.` | 1 to 64 characters; at most 10 components in a path |
| Database | ASCII letters and digits, `-`, `_`, `.`, with `/` between components | 1 to 64 characters for the whole name |
| Branch | Avoid `$` and `:`; use ASCII letters, digits, `-` and `_` for portability | Keep to 1 to 64 characters |
| Secret | ASCII letters and digits, `-`, `_`, `.` | 1 to 128 characters |
| Function {/* if functions launched */} | ASCII letters and digits, `_` | 1 to 128 characters |

Names must be non-empty. A table, view, secret, namespace component or database
component cannot be `.` or `..`. Avoid `$` and `:` in names because they are used
to separate parts of qualified identifiers.

## How do namespace paths work? {#paths}

A namespace path is a list of names. `["prod", "search"]` identifies the
`search` namespace within `prod`. A table named `documents` belongs to that
namespace; its table name remains `documents`.

Use the SDK's namespace-path argument to supply the list. A period inside an
SDK name is a character in that name, not a separator that creates another
namespace. SQL uses its own qualified-name syntax; see
[SQL namespace paths](/sql/dql/select#namespaces).

The empty path `[]` identifies the root namespace. Individual components cannot
be empty, and a path beginning with `public` cannot contain another component.

## What are good examples? {#examples}

| Name or path | Guidance |
| --- | --- |
| `documents`, `user-events.v2`, `train_2026` | Portable table names |
| `["prod", "search"]` | A two-component namespace path |
| `my table` | Use `my_table` instead of a space |
| `orders$2026` | Use `orders_2026`; `$` is reserved |
| `résumés` | Use an ASCII name such as `resumes` |
| `["public", "search"]` | Invalid nesting under `public`; use a different parent namespace |

## Compatibility {#which-versions-check-them}

Validation can happen in the SDK, namespace implementation or Enterprise
service. The point where an invalid name is rejected depends on the client and
server versions. Following the constraints above avoids relying on a backend
accepting a name that another rejects. Your account's database name and namespace
permissions are still assigned by its administrator.
