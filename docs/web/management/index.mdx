Every [catalog object](/basics/catalog) is created, listed, and dropped the same
few ways. This section is the reference for those operations; the pages linked
from it cover what each object is for.

Operations that can take a while have an `_async` form returning a
[job](/basics/jobs).

<Note>

See [Python, TypeScript, and SQL](/basics/apis).
</Note>

## Namespaces qualify everything {#namespace-paths}

Most connection-level operations take a `namespace_path` (`namespacePath`) to
act inside a namespace rather than at the database root:

<CodeGroup>
```python Python icon="python"
db.table_names(namespace_path=["prod", "events"])
tbl = db.open_table("clicks", namespace_path=["prod", "events"])
```

```typescript TypeScript icon="square-js"
await db.tableNames({ namespacePath: ["prod", "events"] });
const tbl = await db.openTable("clicks", { namespacePath: ["prod", "events"] });
```

```sql SQL
SELECT * FROM prod.events.clicks
```
</CodeGroup>

In SQL the path is written as dotted identifiers instead.

## Dropping is not undoable {#dropping}

<Warning>
`drop_table` removes the table and every version of it. Table
[versioning](/tables/versioning) does not survive the table being dropped, and
neither `drop_database` nor `drop_all_tables` asks for confirmation.
</Warning>

Dropping a **view** removes only the saved query. Dropping a **materialized
view** removes stored rows, because a materialized view is a table.
