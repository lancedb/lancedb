A **Secret** is a beta catalog object, like a table or a namespace: a named
credential, such as a model provider's API key, stored once and addressed by
name. A [Function](/curation/create-function) binds a Secret by reference
when you register it, never by value; see
[Vend a Secret to a Function](/curation/vend-secret) for how that binding
reaches running code, and [Secrets](/governance/secrets) for the full
security model -- encryption, redaction, and rotation.

## Create and manage {#manage}

Every call takes an optional `namespace_path`; the default is the root
namespace.

<CodeGroup>

```python Python
db.create_secret("openai-prod", value, namespace_path=["platform"])

db.alter_secret("openai-prod", new_value, namespace_path=["platform"])

for name in db.list_secrets(namespace_path=["platform"]):
    print(name)

info = db.describe_secret("openai-prod", namespace_path=["platform"])
info.created_at_millis, info.updated_at_millis

db.drop_secret("openai-prod", namespace_path=["platform"])
```

```sql SQL
CREATE SECRET platform.`openai-prod` WITH (value = 'sk-...');

ALTER SECRET platform.`openai-prod` SET WITH (value = 'sk-...');

SHOW SECRETS IN platform;

DESCRIBE SECRET platform.`openai-prod`;

DROP SECRET platform.`openai-prod`;
```

```bash REST
# Create. The Secret identifier is its namespace path and name joined by `$`.
curl -X POST "$LANCEDB_HOST_OVERRIDE/v1/secret/platform\$openai-prod/create" \
   -H "Content-Type: application/json" \
   -H "x-api-key: $LANCEDB_API_KEY" \
   -H "x-lancedb-database: $LANCEDB_DATABASE" \
   -d '{"value": "sk-..."}'

# List the names in one namespace.
curl -X GET "$LANCEDB_HOST_OVERRIDE/v1/namespace/platform/secret/list" \
   -H "x-api-key: $LANCEDB_API_KEY" \
   -H "x-lancedb-database: $LANCEDB_DATABASE"
```

</CodeGroup>

| Operation | REST | Returns |
| --- | --- | --- |
| Create | `POST /v1/secret/{id}/create`, body `{"value": ...}` | Nothing. Fails if the name is taken, so a create never silently becomes a rotation. |
| Rotate | `POST /v1/secret/{id}/alter`, body `{"value": ...}` | Nothing. Fails if the Secret does not exist. |
| Describe | `POST /v1/secret/{id}/describe` | `name`, `created_at_millis`, `updated_at_millis`, and `history` |
| List | `GET /v1/namespace/{id}/secret/list` | Names, paginated by `limit` and `page_token`. The root namespace is `$`. |
| Drop | `POST /v1/secret/{id}/drop` | `{"dropped": bool}`. Dropping a Secret that is already gone returns `false`, not an error. |

A Secret's value is never returned by any of these calls, in either
direction: `create` and `alter` take it as input and return nothing, and
`describe` reports only metadata. See the
[SQL reference](/sql/ddl/secret) for the same operations' SQL syntax and
result rows.

<Note>
SQL has no syntax for binding a Secret to a Function. Register Functions that
bind Secrets through the Python SDK or REST; see
[Vend a Secret to a Function](/curation/vend-secret).
</Note>

## Privileges {#privileges}

A Secret is its own object in the [authorization](/governance/authorization)
model, a namespace child like a table, so a grant names one credential
rather than a whole database.

| Operation | Requires |
| --- | --- |
| Create a Secret | `CREATE_SECRET` on the namespace. The creator owns the new Secret. |
| Rotate (`alter`) | `UPDATE` on the Secret |
| Describe | `USAGE` on the Secret |
| List | `USAGE` on the namespace |
| Drop | `OWNERSHIP` on the Secret. Dropping also deletes its grants. |
| Bind it to a Function | `USAGE` on the Secret |

`UPDATE` is deliberately separate from `USAGE`, so a rotation service can
replace a value without being able to bind the Secret to a Function of its
own. See [GRANT and REVOKE](/sql/ddl/secret#grant) for the statements that
assign these privileges.
