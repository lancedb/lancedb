Every other curation task on this page keeps the row count the same or
smaller: profiling, sampling, joining, deduplicating. Chunking goes the other
way -- one source row becomes many derived rows, each carrying its parent's
columns along with it. Use it to split a document into passages for
embedding, a video into clips, or an image into tiles.

## Chunkers {#chunkers}

A [chunker](/geneva/udfs/scalar-udtfs) is a Python function decorated with
`@chunker` that yields one or more output rows per source row, registered as
a view with `create_udtf_view`. A chunker that splits documents into passages
turns a `documents` table into a `chunks` table, inheriting the parent's
columns into every child row:

**Source: `documents`**

| doc_id | title | text |
| --- | --- | --- |
| 1 | "Intro to AI" | "Machine learning is..." |

**Derived: `chunks`** (1:N expansion)

| doc_id | title | chunk_index | chunk_text |
| --- | --- | --- | --- |
| 1 | "Intro to AI" | 0 | "Machine learning..." |
| 1 | "Intro to AI" | 1 | "Neural networks..." |
| 1 | "Intro to AI" | 2 | "Training data..." |

<CodeGroup>
```python Python icon="python"
from typing import Iterator, NamedTuple

import geneva
from geneva import chunker

class Passage(NamedTuple):
    chunk_index: int
    chunk_text: str

@chunker
def split_into_passages(text: str) -> Iterator[Passage]:
    for index, passage in enumerate(text.split("\n\n")):
        yield Passage(chunk_index=index, chunk_text=passage)

db = geneva.connect("/data/mydb")
documents = db.open_table("documents")

chunks = db.create_udtf_view(
    "chunks",
    source=documents.search(None).select(["doc_id", "title", "text"]),
    udtf=split_into_passages,
)
chunks.refresh()  # runs the chunker over every source row
```
</CodeGroup>

The chunker view is a materialized view, so it refreshes incrementally: new
source rows are chunked and inserted, deleted source rows cascade-delete their
children, and an updated source row's old children are replaced by freshly
chunked ones. See [Chunkers](/geneva/udfs/scalar-udtfs) for the full `@chunker`
decorator (including a batched form for vectorized chunking) and
`create_udtf_view` reference.

## Under the hood: LATERAL UNNEST {#lateral}

A chunker view runs each source row's chunker call and explodes its list of
results into one row per element, using the engine's `LATERAL UNNEST`
support. You reach for this directly, without a chunker, when you already
have a list-typed column and just want to explode it in one query -- for
example a `tags` column produced by an earlier step:

<CodeGroup>
```python Python icon="python"
db.execute_query("""
    SELECT *, UNNEST(tags) AS tag FROM documents
""")
```
</CodeGroup>

Each source row with three tags becomes three output rows, one per tag, with
every other column repeated. This is the same mechanism a chunker view
compiles down to; the chunker just produces the list (and the row count it
unnests to) from arbitrary Python instead of a column that already exists.
