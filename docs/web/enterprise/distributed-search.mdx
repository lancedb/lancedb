Distributed search spreads index execution, table-data reads, and caching across
multiple serving machines in LanceDB Enterprise. Query nodes plan queries and
combine results. Plan executors cache index structures and table data and execute
the remote work -- see [Data Page Cache](/enterprise/data-page-cache) and
[Tiered Index Cache](/enterprise/tiered-index-cache) for how each cache works.
See [Architecture](/index#architecture).

## Expected performance {#performance}

These are the out-of-the-box latency and throughput LanceDB Enterprise
reaches on fully cached data, with no custom tuning -- a representative
floor, not a ceiling. [Talk to support](https://www.lancedb.com/contact)
to reduce latency or increase throughput further for your workload.

### Vector search {#performance-vector}

Measured with 1,536-dimensional embeddings, an IVF-RQ index, `nprobe=8`,
`k=100`, on the best-performing (fully cached) configuration tested at
each scale:

| Rows | QPS | p50 | p99 |
| --- | :-: | :-: | :-: |
| 100M | 31.7 | 46 ms | 268 ms |
| 500M | 588.3 | 26 ms | 45 ms |
| 1B | 817.3 | 28 ms | 58 ms |
| 5B | 453.2 | 47 ms | 160 ms |
| 30B | 650.3 | 84 ms | 206 ms |

### Full-text search {#performance-fts}

Measured under a mixed workload of phrase, match-any and match-all
queries, with an ICU-tokenized FTS v3 index (positions and lowercasing
enabled, stemming disabled):

| Rows | QPS | p50 | p99 |
| --- | :-: | :-: | :-: |
| 100M | 758.2 | 28 ms | 64 ms |
| 500M | 759.6 | 49 ms | 183 ms |
| 1B | 702.0 | 62 ms | 274 ms |
