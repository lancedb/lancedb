**LanceDB** is a [multimodal lakehouse](https://lancedb.com/blog/multimodal-lakehouse/) for AI. It gives you one data
layer for search and retrieval, curation, feature engineering, and model training. It is built on [Lance](/basics/lance), an
open-source columnar format for multimodal AI data.

Raw data, metadata, embeddings, and features live together in one versioned table, stored in open files on local
disk or object storage. You search the table, curate it, add derived columns, and stream it into training without
copying data into a separate system for each step.

LanceDB includes:

- [**Multimodal tables**](/management/table#multimodal) that hold images, video, audio, text, embeddings, and
  metadata in one schema-enforced table
- [**Vector search**](/search/vector-search), combined with [filters](/search/filtering) and
  [reranking](/reranking)
- [**Full-text search**](/search/full-text-search) with BM25 ranking, and
  [**hybrid search**](/search/hybrid-search) that fuses it with vector results
- [**Versioning**](/management/table#versioning) that traces each training run back to the exact data it used
- [**Training data loading**](/training/data-loading) that streams shuffled, deterministic batches into PyTorch
- [**Curation**](/curation) with sampling, deduplication, chunking, and joins (Enterprise)
- [**Computed columns**](/feature-engineering/add-computed-column) and
  [**materialized views**](/feature-engineering/materialized-views) that refresh as data changes (Enterprise)
- [**SQL**](/basics/sql) over the same tables, through Arrow Flight SQL (Enterprise)
- [**SDKs**](/basics/sdk) for Python, TypeScript, and Rust

## Architecture {#architecture}

LanceDB ships as two offerings on the same Lance format and table model, so moving from one to the other needs no
data conversion.

    <img src="/static/assets/images/overview/lancedb-embedded.png" alt="LanceDB Embedded architecture" />
  </Frame>
  <Frame caption="In LanceDB Enterprise, the SDK connects to a service whose query fleet, executor and cache fleets, realtime engine, and jobs fleet run on the Lance format and object storage.">
    <img src="/static/assets/images/overview/lancedb-distributed.png" alt="LanceDB Enterprise architecture" />
  </Frame>

- [**LanceDB Embedded**](/basics/lancedb-embedded) is open source and runs inside your application's process, with
  no server to deploy. It is limited to the resources of one host, and your application runs compaction and
  indexing.
- [**LanceDB Enterprise**](/enterprise/index) runs query execution, indexing, caching, and maintenance on a
  distributed service outside your application, in your cloud or managed by LanceDB. It adds a service to deploy
  and size, in return for capacity that grows with the cluster and maintenance that runs in the background.

See [Embedded vs Enterprise](/basics/embedded-vs-enterprise) for a feature-by-feature comparison.

Teams use LanceDB for world-model and robotics training, as in
[stable-worldmodel](https://github.com/galilai-group/stable-worldmodel) and
[lerobot-lancedb](https://github.com/lancedb/lerobot-lancedb), and for agent memory, as in
[CrewAI](https://www.lancedb.com/blog/crewai-rebuilt-agent-memory-on-lancedb),
[Cognee](https://github.com/topoteretes/cognee), and
[OpenClaw](https://docs.openclaw.ai/plugins/memory-lancedb).

To get started, see the [quickstart](/quickstart).
