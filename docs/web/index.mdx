**LanceDB** is a [multimodal lakehouse](https://lancedb.com/blog/multimodal-lakehouse/) for AI. It gives you one data
layer for search and retrieval, curation, feature engineering, and model training. It is built on [Lance](/basics/lance), an
open-source columnar format for multimodal AI data.

LanceDB depends only on object storage for its primary state, and NVME/memory for caching in the serving
layer, giving it the latency profile of an in-memory database with the petabyte scalability and cost profile
of S3. LanceDB is intended for use as a single solution in your org, giving your team one system to
become expert in and removing the need for multiple database systems and synchronization pipelines
between them. Core features include:

- [**SQL**](/basics/sql) powered by Apache DataFusion (Enterprise)
- [**Secondary indexes**](/indexing) for vector search, full-text search, and scalar filters
- [**Computed columns**](/feature-engineering/add-computed-column) with on-demand or scheduled refresh (Enterprise)
- [**Materialized views**](/feature-engineering/materialized-views) with on-demand or scheduled refresh (Enterprise)
- [**Time travel and versioning**](/management/table#versioning) to pin and revisit datasets
- **Search**: [vector](/search/vector-search), [full-text](/search/full-text-search), and
  [hybrid](/search/hybrid-search), with [filters](/search/filtering) and [reranking](/reranking)
- [**Python UDFs**](/curation/create-function) for custom transformations and model inference (Enterprise, early access)
- [**Row-level random access**](/basics/lance#capabilities) for retrieval and training
- [**Column additions**](/management/table#schema-add-new-columns) without rewriting existing columns

LanceDB stores images, video, audio, text, embeddings, and metadata in
[schema-enforced tables](/management/table#multimodal). In LanceDB Enterprise, these features let you build
declarative ML data pipelines: ingest raw data and metadata, enrich it incrementally with computed columns and
Python UDFs, and organize it into [curated datasets](/curation) with materialized views. Add features without
rewriting existing columns, then train from those datasets using row-level random access and sampling.

LanceDB provides [SDKs](/basics/sdk) for Python, TypeScript, and Rust, plus a
[PyTorch data loader](/training/data-loading) for reproducible shuffling and streaming batches.

## Architecture {#architecture}

LanceDB ships as two offerings on the same Lance format and table model, so moving between them requires no data conversion. Start 
locally with Embedded, then move to Enterprise for distributed scale, feature engineering, managed infrastructure, and enterprise support.

<CardGroup cols={2}>
  <Card title="LanceDB Embedded" icon="cube" href="/basics/lancedb-embedded">
    An open-source, embedded retrieval library that runs inside your application process, with no separate
    database server to deploy.
  </Card>
  <Card title="LanceDB Enterprise" icon="server" href="/enterprise/index">
    Runs queries and feature engineering across a cluster, with background indexing and maintenance.
    Deploy it in your cloud or use a LanceDB-managed deployment.
  </Card>
</CardGroup>

See [Embedded vs Enterprise](/basics/embedded-vs-enterprise) for a feature-by-feature comparison, including
architecture, latency, throughput, and day-to-day usage differences.

## Projects using LanceDB

Teams use LanceDB for world-model and robotics training, as in
[stable-worldmodel](https://github.com/galilai-group/stable-worldmodel) and
[lerobot-lancedb](https://github.com/lancedb/lerobot-lancedb), and for agent memory, as in
[CrewAI](https://www.lancedb.com/blog/crewai-rebuilt-agent-memory-on-lancedb),
[Cognee](https://github.com/topoteretes/cognee), and
[OpenClaw](https://docs.openclaw.ai/plugins/memory-lancedb).

To get started, see the [quickstart](/quickstart).
