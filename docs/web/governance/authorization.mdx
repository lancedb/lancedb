[Authentication](/enterprise/authentication) establishes who is calling.
Authorization decides what they may do.

An access control entry grants **one privilege** on **one object** to **one
subject**. Everything on the Principals and Privileges pages is a
consequence of that shape.

## Granting a privilege {#granting}

`GRANT` and `REVOKE` cover a Secret or a namespace today, the objects a
day-to-day user shares most often:

<CodeGroup>
```sql SQL icon="database"
GRANT USAGE ON SECRET platform.`openai-prod` TO ROLE research
REVOKE USAGE ON SECRET platform.`openai-prod` FROM ROLE research
```
</CodeGroup>

The caller must already hold `OWNERSHIP` on the object being granted, and
the role, user or group named need not already exist.

See [Privileges](/governance/privileges) for the full statement syntax,
every privilege each operation needs, and the broader set of privileges --
covering databases, tables, views and materialized views -- that the REST
ACL API grants today, ahead of SQL. See [Principals](/governance/principals)
for who a grant can name.
