Use `update` to change rows selected by a predicate. Use
[merge insert](/ingestion/merge-insert) instead when matching an incoming dataset
against existing keys.

## Select the rows to change {#select-rows}

Check the predicate with a [filtered query](/search/filtering) before applying
the update. These examples target the row with `id = 2`. Review the scope
carefully when omitting a predicate, since that can update the entire table.

Each example below starts from Alice with 10 logins and Bob with 20. The
Python programs create and remove their own temporary database. TypeScript
and Rust operation blocks use `db`; a complete program is provided below.

## Verify the affected data {#verify}

Read the selected rows again and inspect the changed fields. For another
connection or table handle, account for its
[read consistency](/tables/consistency) settings.

Nested-field updates are not supported by these operations. For schema changes,
see [schema evolution](/management/table#schema). Treat derived values separately:
changing an input field is not a guarantee that every stored feature has been
recomputed. See [Refresh a column](/feature-engineering/refresh-column).

Updates can change index coverage and query cost. After a large update,
inspect the workload and follow [index maintenance](/indexing/reindexing)
guidance for the backend you use.
