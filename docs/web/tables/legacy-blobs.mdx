Use [`lancedb.blob()`](/tables/multimodal#multimodal-blob-v2) for new tables. The sections below
cover existing tables that use the V1 large-binary Blob API
(`pa.large_binary()` in Python, `LargeBinary` in TypeScript, and
`DataType::LargeBinary` in Rust with `{"lance-encoding:blob": "true"}` field
metadata). Changing a field's metadata alone does not migrate an existing V1
column to Blob v2.

Start with the SDK imports and local `db` connection from
[Blob setup](/tables/multimodal#multimodal-blob-v2-setup).

## 3\. Convert blob tables to pandas {#multimodal-3-convert-blob-tables-to-pandas}

On LanceDB Embedded tables with V1 blob columns, `to_pandas()` in Python accepts
`blob_mode` (`"lazy"`, `"bytes"`, or `"descriptions"`). Enterprise tables raise
`NotImplementedError`, and `"bytes"` is not supported on in-memory tables.
Extra keyword arguments such as `split_blocks` or `self_destruct` are forwarded
to the PyArrow / Lance pandas conversion:

<CodeGroup>
    <CodeBlock filename="Python" language="Python" icon="python">
    {LegacyBlobApiToPandas}
    </CodeBlock>
</CodeGroup>

The query examples also assume an async table named `tbl_async` and a query
vector named `query_vector`. On query builders with V1 blob columns, plain scans support `"lazy"`, `"bytes"`,
and `"descriptions"`. Vector, FTS, hybrid, and ordered queries cannot
materialize V1 blob columns through `to_pandas()`, so omit those columns from
the projection:
