Change a table's schema as your data requirements evolve. This guide covers
adding and dropping columns. For other changes, see [Alter columns](/tables/alter-columns)
and [Field metadata](/tables/field-metadata).

<Note>
In SQL, schema changes are [`ALTER TABLE`](/sql/ddl/table#alter).
</Note>

## Schema evolution operations {#schema-schema-evolution-operations}

LanceDB supports four primary schema evolution operations:

1. **Adding new columns**: Extend your table with additional attributes
2. **[Altering existing columns](/tables/alter-columns)**: Change column names, data types, or nullability
3. **[Updating field metadata](/tables/field-metadata)**: Attach or change per-column Arrow metadata
4. **Dropping columns**: Remove unnecessary columns from your schema


<Tip title="Schema Evolution Performance">
Schema evolution operations are applied immediately but do not typically require rewriting all data. However, data type changes may involve more substantial operations.
</Tip>

Each schema evolution operation commits a new table version and returns status metadata such as
the committed `version`. Run these operations from a mutable table handle; if you checked out an
older version for reads, call `checkout_latest` / `checkoutLatest` before modifying the schema.

The examples use a local database connection named `db`; see [Connect to LanceDB](/quickstart#connect-via-local-directory-path).
Run each setup before the operations that follow it.

## Add new columns {#schema-add-new-columns}

You can add new columns to a table with the [`add_columns`](https://lancedb.github.io/lancedb/python/python/#lancedb.table.Table.add_columns)
method in Python, [`addColumns`](https://lancedb.github.io/lancedb/js/classes/Table/#addcolumns) in TypeScript/JavaScript, or `add_columns` in Rust.
New columns are populated based on SQL expressions you provide. On local tables,
the Python SDK also accepts precomputed values from DataFrames and Arrow readers;
see [Create a computed column](/feature-engineering/add-computed-column#computed-vs-transforms)
for the supported inputs and row-order requirements.

<Warning title="Dropping a column is undone only by restoring a version">
Dropping a column changes the latest version only. Until
[cleanup](/maintenance/cleanup) prunes the versions from before the drop,
[restoring](/tables/versioning) one of them brings the column and its values back,
along with the rest of the table as it was then. Once those versions are
pruned, the drop cannot be undone, so check before dropping a column you may
need.
</Warning>
